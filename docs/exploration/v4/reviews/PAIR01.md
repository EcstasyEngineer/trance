# Pair 01: Accelerate and Animation

Verdict: both fit three authored container kinds (`parallel`, `sequential`, `random`). Neither requires authored registers or burst phases. This is a reduction in composition kinds, not permission to remove duration, repetition, offset, opacity, source selection, or local/ancestor progress.

## Accelerate

Observed source: `src/trance/visual/builtin_patterns_v3.cpp`, visual 1. An outer 2048-frame parallel composition contains a 140-cut accelerating sequence plus a continuously rendered spiral. Each cut concurrently owns an image and a probabilistic word accent. No random container is needed: a probability on an operation is different from choosing which child composition runs.

Minimum AST representation:

- Parallel scene, duration 2048 frames.
- Sequential cut lane whose 140 child occurrences are generated by a timing property: shape 56 to 12, early cubic easing, normalize to scene duration.
- Each occurrence is a parallel body containing one image and one word. The repeated authored image operation has one stable identity across all generated occurrences.
- Image source alternates with flip probability 0.5; this is not draw probability. Animation accent is every fourth selection. Word draw probability is separately 0.5 and its visibility window is the first quarter of the cut.
- Whole-scene origin progresses 0 to 0.4. Zoom equals that origin plus a local 0 to 0.1 pop. Spiral speed progresses 1 to 4 on the scene clock.

The current ramp sampler (`pattern_parser_v3.cpp::sample_ramp`) samples at segment midpoints, scales all durations to sum to 2048, rounds, then distributes residual error from the tail. Calling the endpoints literal first/last durations would change pacing: they determine shape, not absolute tempo. Preserve the sampler or explicitly label the change.

Removing expression syntax is possible only if the AST still represents this additive zoom: an explicit base/offset plus local motion range is sufficient for this builtin. Removing the behavior because the expression is awkward would reintroduce the documented black-bar/violent-pop regression. Suggest a structured `zoom { base: sceneOrigin, from: 0, to: 0.1 }` model rather than free-form arithmetic for this case.

Exact comparison invariants:

1. Same 140 start frames, segment lengths, and 2048-frame sum; no zero-length segments.
2. 140 image picks and 35 animated cuts per scene over at least four scenes; animation and alternate state survive occurrence expansion and scene reset as they currently do.
3. Per-frame image zoom/origin and spiral speed equal baseline, with ancestor progress independent of cut progress.
4. Under a deterministic injected random stream, same toggle, word-visibility, and selection traces. Preserve random-call order if claiming exact seeded parity.
5. Second output render pass performs no additional picks, loads, or policy advancement.

Existing evidence: `tests/animation_accent_composition_test.cpp` already traces Accelerate for four scenes and checks 140 cuts/35 accents and multi-output invariance. Its identity checks distinguish three chance sites from one authored animation and alternate policy. It does not by itself compare every pixel or seeded word outcomes.

## Animation

Observed source: builtin visual 7. A 1024-frame parallel scene contains two independent image lanes, captions, and spiral. The lower lane selects animated content every 64 frames. The upper still lane also selects every 64 frames, offset 48 frames, with an 8-frame rise, 16-frame hold, 8-frame fall, then genuine absence.

Minimum AST representation:

- Parallel scene and two independent parallel lane scopes. Their image ownership must remain separate even if a wrapper has only one child.
- Repeat timing property: period 64; upper lane phase offset 48. These are timing properties on a composition, not fourth/fifth composition kinds.
- Image leaf animation policy `always` on the lower lane; still-only on upper lane.
- Opacity shape on upper lane: rise 8, hold 16, fall 8, absent remainder. Caption period 32; spiral speed 3.
- Source policy lower/captions `random-theme`, upper `secondary`. `runtime` is a misleading name for random primary/secondary choice at firing; it is not a clock.

The offset is phase alignment, not a 48-frame startup delay. `OffsetCycler::advance_to_offset` pre-advances without actions. Replacing it with a delayed sequence gives different initial opacity and lifecycle. Image replacement events and render progress also need separate treatment: initialization must not consume extra media picks while pre-rolling.

Exact comparison invariants:

1. Recording renderer retains layer order: animated lower image then visiting still, captions, spiral.
2. Across a complete 64-frame turn after normal initialization: upper alpha has 33 absent frames, 17 full frames, 14 intermediate frames under current endpoint convention. Do not silently substitute a triangular fade, which lacks the long absence/hold.
3. Each lane picks 16 images per 1024-frame scene; lower attempts animation every selection. Caption selection every 32 frames.
4. Upper zoom progresses 0.5 to 0.625 on its own 64-frame image lifetime; lower progresses 0 to 0.625 on its own lifetime. Offset does not change the scene duration.
5. Repeat boundary, explicit reset, theme refresh, missing animation fallback, and second render pass preserve independent ownership and selection behavior.

## Consolidation boundary

Only three composition kinds is coherent. A sequential container with a repeated parallel body expresses cadence; a sequential container with a generated duration schedule expresses acceleration. Opacity envelopes remain leaf motion properties. The AST must distinguish composition choice, timing, content source policy, and leaf animation policy instead of giving all of them the word `random` or deleting them. For these two patterns, random source choice does not justify a random child-controller wrapper.

This review read actual builtin source, ramp/envelope/animation parser lowering, compiled source-slot resolution, offset/phase scheduler code, and the authored-policy regression test. It does not claim a V4 parser or end-to-end V4 trace exists yet.
